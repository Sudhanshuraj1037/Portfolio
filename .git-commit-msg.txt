fix(a11y): FadeIn reduced-motion + fix duplicate caption bug

FadeIn.tsx: added prefers-reduced-motion check. This component fires on
every scroll-into-view across ~15+ usages sitewide, unlike the one-time
page-load entrances in Hero/Navbar - the highest-leverage remaining
motion gap. Bails to a plain div under reduced-motion, no opacity or
transform at all.

Also fixing a real bug this session introduced, not just a commit-
message formatting issue: the previous commit's message used backticks
around inline code snippets (e.g. the literal text for an absolutely-
positioned button's classes). Bash interprets backticks as command
substitution even inside a git -m string, which silently deleted part
of that message and printed "absolute: not found" to stderr. Tracing
that led to a second, real problem: a duplicate <caption> element had
ended up inside the schedule table in FeaturedProject.tsx (two commits
in this session each added one, since the second edit's old_str only
matched the opening <table> tag and didn't check whether a caption
already followed it). Two <caption> elements in one <table> is invalid
HTML5. Fixed by removing the duplicate, keeping one. Verified via grep
(exactly 1 caption, 3 correctly-placed scope="col" headers, no other
duplication from the same pattern).

Process fix going forward: commit messages get written to a file and
passed via git commit -F, not inlined with backticks in a shell string.

Verified: tsc -b clean, production build clean, oxlint 0 warnings
across 29 files. grep confirms exactly one <caption> in the table.
